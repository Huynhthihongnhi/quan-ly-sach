## TDD notes

- BE: wrote the failing `restricts the admin queue list to purchases.read.any` case first (confirmed RED: 404, endpoint did not exist), then added the DTO/repository/service/controller method; reran to GREEN.
- CMS: the double-click test and the conflict test each caught a real bug during development, not just confirmed the happy path:
  - Idempotency key builder used a 57-character attempt-id limit copied from the `borrow:` precedent (7-char prefix) without adjusting for the `purchase:` prefix (9 chars), which could exceed the BE's 64-character `Idempotency-Key` limit by 2 characters. Fixed the limit to 55.
  - `AdminPurchaseQueuePage` originally reused the same `error` state for both list-load failures and the conflict notice; a successful refetch after a conflict immediately cleared the notice via `setError(null)`, so the "reviewed elsewhere" message never reached the user. Fixed by introducing a separate `notice` state that `load()` does not touch, and by clearing the status filter on conflict so the row (which may have left the "Pending" filter) stays visible with its real state.
